Enhancement One

Software Design & Engineering

Artifact Overview

This artifact is my Evidence Tracker Android application, originally developed during CS 360: Mobile Architecture and Programming. Although the original assignment was designed as an inventory management application, I redesigned it into an evidence management system that reflects professional crime scene workflows. This enhancement focuses on improving the application's software architecture, maintainability, and security through software engineering best practices.

Why I Selected This Artifact

I selected this application because it demonstrates my ability to apply software engineering principles to solve a real-world problem. As a Crime Scene Investigator, I understand that evidence management requires secure workflows, dependable software, and clearly defined user responsibilities. Enhancing this project allowed me to combine my professional experience with software engineering while transforming a classroom assignment into a more realistic evidence management system.

The original application successfully supported authentication and evidence management but lacked role-specific permissions, administrator approval, and modular organization. These limitations created an opportunity to redesign the application by improving maintainability, security, and overall software architecture.

Software Design Enhancements

The enhancement introduced role-based access control supporting Administrators, Crime Scene Investigators, and Detectives. Administrator approval of new accounts, dedicated user management, secure authentication, and authorization logic were added to better reflect professional evidence management systems.

Evidence management responsibilities were also separated into dedicated activities, improving maintainability while reducing complexity within the original application. These changes created a cleaner architecture that is easier to understand, maintain, and expand.

Authentication & User Registration

The enhanced application requires users to authenticate before accessing evidence records. The login screen restricts the system to authorized personnel and provides a separate option for new users to request an account.

During registration, users enter identifying information and select an organizational role. The account is not immediately activated. Instead, it remains pending until an administrator reviews the request.

Administrator Approval Workflow

A new administrator approval workflow prevents account registration from automatically granting application access. New accounts remain in a pending state until an administrator reviews the request.

The main administrator dashboard displays the number of requests awaiting review. Administrators can then open the pending-requests page and approve or reject each account based on the requested role and user information.

Role-Based Access Control

Role-based access control limits application functions according to each user's responsibilities. Crime Scene Investigators can add and update evidence records, while Detectives receive read-only access. Administrative functions remain limited to approved administrators.

Crime Scene Investigator

  • View evidence
  • Add evidence
  • Update evidence
  • Manage user accounts
  • Approve account requests

Detective

  • View evidence
  • Add evidence
  • Update evidence
  • Delete evidence
  • Manage user accounts

User Management

Administrators have access to a dedicated user management interface where approved accounts can be reviewed, edited, or disabled. Each account displays the user's name, username, email address, and assigned role.

The interface also identifies the currently logged-in administrator. This distinction helps prevent unintended account changes and supports safer administrative control.

Enhancement Results

The redesigned application now supports multiple user types with clearly defined permissions. Authentication protects evidence records from unauthenticated access, while the approval workflow gives administrators control over who can enter the system.

The user interface also communicates available functions according to the active role. Users are not simply warned that an action is restricted; unavailable controls are removed from their interface. This creates a more usable design while reducing opportunities for unauthorized actions.

Reflection

What I Learned

This enhancement reinforced that software engineering involves much more than adding new functionality. Throughout the redesign, I learned the importance of separating responsibilities into dedicated activities, improving maintainability, and enforcing security through application logic rather than relying solely on interface controls. Refactoring the application into specialized components created a cleaner architecture that is easier to understand, test, and extend.

One of the greatest challenges involved restructuring the application while preserving existing functionality. Database operations, authentication, RecyclerView updates, navigation, SMS notifications, and role-based permissions all had to continue working together after the redesign. Incremental testing and careful planning allowed each enhancement to be integrated without disrupting the application's existing features, reinforcing the importance of thoughtful software design and comprehensive testing.

Course Outcome Reflection

This enhancement primarily demonstrates Course Outcomes One, Two, Four, and Five . It strengthened my ability to evaluate an existing software artifact, apply software engineering principles to improve application architecture, and develop a secure solution that addresses an industry-specific problem. Implementing role-based access control, administrator approval workflows, and modular application design also reinforced the importance of creating software that is both maintainable and aligned with professional development practices.

Although this enhancement focused primarily on software design and engineering, it also established the foundation for the algorithm and database enhancements completed later in the capstone. Together, these improvements transformed the original classroom inventory application into a more realistic evidence management system while demonstrating my growth in Android development, secure application design, software testing, and professional software engineering.
