Initial Artifact Analysis

Code Review

The code review served as the starting point for the CS 499 capstone project. During the review, I examined the original Evidence Tracker application to evaluate its structure, functionality, maintainability, security, and database design.

The review helped identify areas where the application could be improved through software design and engineering, algorithms and data structures, and database enhancements. These findings guided the work completed throughout the remainder of the capstone.

Original Artifact

The artifact selected for the capstone was an Android application originally created in CS 360: Mobile Architecture and Programming. The original project was designed as an inventory management application that allowed users to create an account, log in, and perform basic create, read, update, and delete operations using a local SQLite database.

I later adapted the project into an Evidence Tracker because the subject closely aligns with my professional experience as a Crime Scene Investigator. Although the application provided a functional foundation, the review identified several opportunities to improve its architecture, security, usability, and data management.

Areas Evaluated

1 Software design, application structure, authentication, authorization, and user experience.
2 Algorithms and data structures used to search, organize, validate, and process evidence records.
3 SQLite database structure, table relationships, queries, data integrity, and scalability.
4 Code readability, maintainability, error handling, and opportunities for future development.

Key Findings

The original application successfully demonstrated the core requirements of the CS 360 project, including account creation, user login, persistent SQLite storage, and standard CRUD operations. These features provided a useful foundation for the capstone enhancements.

The review also identified several weaknesses. User roles were not clearly separated, new accounts did not require administrative approval, and access to application functions was not sufficiently restricted. The inventory-based structure also lacked the specialized fields and workflows needed for evidence management.

Additional opportunities existed to improve evidence searching, sorting, validation, database organization, and the long-term maintainability of the codebase.

Enhancement Plan

Software Design & Engineering

  • Add secure authentication
  • Implement administrator approval
  • Add role-based access control
  • Improve navigation and usability

Algorithms & Data Structures

  • Improve evidence retrieval
  • Add search and sorting logic
  • Strengthen validation
  • Improve processing efficiency

Databases

  • Redesign the SQLite schema
  • Add evidence-specific fields
  • Improve table relationships
  • Strengthen data integrity

Reflection

Conducting the code review helped establish a clear understanding of the application's strengths and weaknesses before development began. Rather than immediately changing the code, I first examined the system as a whole and considered how each planned enhancement would affect the user interface, application logic, and database.

This process provided a structured roadmap for the capstone and reduced the likelihood of making isolated changes that would not support the larger goals of the application. It also reinforced the importance of reviewing existing software before beginning a major redesign.
